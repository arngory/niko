# Анти-DPI: TCP и UDP, и что это значит для Niko

Исследование для клиента Niko и niko-server/raycontrol. Дата: 2026-11-01.

Уровень доверия к источникам:
- **[проверено]** — подтверждено нашим кодом или тестами;
- **[источник]** — документация проекта или исследование;
- **[сообщают]** — форумы и блоги. Такие данные зависят от оператора и региона, их надо перепроверять на тестовых точках (решение L-2 raycontrol: RU, CN, KZ, KG, UZ).

## 1. Что делает DPI сейчас (Россия, ТСПУ)

- **SNI из TLS по TCP.** Фильтр собирает ClientHello из нескольких сегментов, поэтому простой разрез имени по пакетам больше не прячет его. [сообщают: [Хабр, «Пожалуй, все что надо знать о ТСПУ»](https://habr.com/ru/articles/1095490/)]
- **SNI из QUIC.** Фильтр расшифровывает Initial (ключи выводятся из DCID и известны всем) и проверяет SNI так же, как в TCP. [сообщают: там же]
- **Блок по объёму на мобильных сетях** (МТС, Билайн, МегаФон, Yota). Соединение к IP иностранного хостинга (Hetzner, DigitalOcean и т. п.) молча замирает примерно после 25 пакетов (около 16 КБ). Это касается TLS-протоколов: VLESS, REALITY, Trojan, Shadowsocks. Исключения — белый список SNI, белый список подсетей и SSH. По одному из выводов, предел действует и для UDP. [источник: [net4people/bbs #490](https://github.com/net4people/bbs/issues/490), [сводка](https://corpus.lantern.io/papers/2025-hyperion-cs-censor-has-new/); проверка — [hyperion-cs/dpi-checkers](https://github.com/hyperion-cs/dpi-checkers)]
- **Белые списки на мобильных сетях.** UDP режется почти целиком, включая QUIC, DNS к чужим серверам и WireGuard. Проходит в основном то, что похоже на разрешённые сервисы. [сообщают: [Хабр, белые списки](https://habr.com/ru/articles/1027276/)]
- **Постквантовый ClientHello.** С X25519MLKEM768 ClientHello вырастает примерно до 1,8 КБ. Разрез по первому байту (`-s 1` в ByeDPI) после этого перестал помогать: имя оказывается во втором фрагменте, и его находят. [сообщают: [byebyedpi.org](https://byebyedpi.org/byebyedpi-rostelecom/)]

## 2. Каталог техник

| Техника | TCP | UDP | Нужен root на Android | Что нужно от сервера |
|---|---|---|---|---|
| Разрез данных по сегментам (split, multisplit) | да | — | нет (границы `write` + `TCP_NODELAY`) | ничего |
| Разрез TLS-записи (tlsrec) | да | — | нет | ничего |
| Перестановка (disorder) | да | да (порядок датаграмм) | нет для UDP; для TCP — фейк с TTL | ничего |
| Фейк с низким TTL | да | да | **нет** (`IP_TTL`/`IPV6_UNICAST_HOPS` на своём сокете) | ничего, если TTL точный; иначе сервер должен отбрасывать фейк |
| Фейк с битой контрольной суммой, md5sig | да | да | да (raw sockets) | — |
| Фейк «известного» протокола (fakeknown: QUIC Initial, WireGuard) | — | да | нет | отбросить фейк |
| Изменение длины (udplen) | — | да | нет, если протокол терпит padding | протокол должен терпеть padding |
| Фрагментация IP (ipfrag2) | да | да | да на практике; без root ядро режет только больше MTU | ничего; некоторые туннели ломает [сообщают] |
| Окно TCP (wsize) — сервер вынуждает клиента резать данные | да | — | — | **настройка на сервере** |
| Маскировка под разрешённый протокол (сигнатурные пакеты) | — | да | нет | сервер отбрасывает сигнатурные пакеты |
| Ротация портов (port hopping) | — | да | нет | слушать диапазон портов |
| Полная обфускация (нет сигнатуры вообще) | да | да | нет | общий ключ |

Где эти техники уже есть:
- **zapret (nfqws)** умеет UDP: десинхронизацию для любого протокола, `fake` с повторами для QUIC, `fakeknown`, `udplen` (в том числе с уменьшением длины), `ipfrag2`. Работает через NFQUEUE, то есть нужен root. [источник: [зеркало zapret, docs/changes.md](https://git.drygdryg.lds.net.ru/drygdryg/zapret/src/commit/03312cbb67462a45cb0624de217730e7dd840866/docs/changes.md)]
- **ByeDPI** — SOCKS-прокси в пространстве пользователя, root не нужен. Для UDP есть `--udp-fake <n>` (n фейковых пакетов перед первым) и `--fake-data`. По сообщениям, порядок аргументов важен. [источник: README, [AUR](https://aur.archlinux.org/packages/byedpi); сообщают: [ntc.party](https://ntc.party/t/byedpi-%D0%BE%D0%B1%D1%81%D1%83%D0%B6%D0%B4%D0%B5%D0%BD%D0%B8%D0%B5/9057?page=23)]
- **AmneziaWG 1.5/2.0** перед каждым рукопожатием (раз в 120 с) отправляет до пяти пакетов I1–I5 на языке CPS. I1 — снимок настоящего протокола (QUIC Initial, DNS, SIP), I2–I5 добавляют энтропию. Плюс мусорные пакеты Jc и обфускация заголовков. [источник: [документация Amnezia](https://docs.amnezia.org/en/documentation/amnezia-wg), [блог](https://amnezia.org/blog/amneziawg-2-0-available-for-self-hosted)]

## 3. Можно ли переносить техники на UDP «с согласованностью»

**Можно, и у нас для этого лучшая позиция.** zapret и ByeDPI вынуждены угадывать поведение чужого сервера: фейк нужно подобрать так, чтобы DPI его увидел, а сервер нет (точный TTL, битая контрольная сумма). Мы управляем обеими сторонами: клиентом Niko и udpmux niko-server. Поэтому фейку не нужен точный TTL. Его достаточно сделать таким, чтобы **наш сервер гарантированно его отбросил**: пакет не расшифровывается, не проходит классификацию, у него чужой SNI.

### Правило согласованности для udpmux (в SPEC)

udpmux отбрасывает пакет, который не прошёл классификацию, и **не запоминает поток по такому пакету**. Поток закрепляется только по первому верному пакету. Без этого правила фейк закрепил бы поток за drop, и настоящий пакет следом бы потерялся.

### Что делать в клиенте, по приоритету

1. **UDP-прелюдия для Hysteria2, TUIC и naive-quic.** Перед первым настоящим пакетом потока отправить N (1–6) фейков с того же сокета:
   - вариант «случайные байты» случайной длины;
   - вариант «QUIC Initial с SNI из белого списка». Это настоящий QUIC Initial со случайным DCID и разрешённым SNI. DPI, который классифицирует поток по первому Initial, видит разрешённое имя.

   Наш сервер отбрасывает оба варианта: первый не классифицируется, у второго SNI нет в таблице маршрутов. Для сторонних серверов прелюдия работает с низким TTL (`IP_TTL`), и фейк до них не доходит. Это аналог I1–I5 у AWG, только для QUIC.
   - **Реализация:** в sing-quic (вендорен в `third_party`) — хук «до первой записи в сокет»; в профиле — число пакетов, вид и TTL.
   - **Риск:** «QUIC Initial с чужим SNI» к стороннему серверу без TTL-ограничения вызовет у него ответ. Поэтому для сторонних серверов — только с TTL.
2. **Разрез и перестановка CRYPTO во QUIC Initial.** Это аналог разреза ClientHello в TCP, только сильнее:
   - ClientHello по CRYPTO-фреймам раскладывается в 2–3 Initial-пакета так, чтобы SNI оказался не в первом;
   - пакеты уходят в обратном порядке.

   QUIC по стандарту собирает CRYPTO по смещениям, поэтому любой сервер (quic-go, наш niko-server) примет такой поток **без изменений на своей стороне**. DPI, который собирает только первый Initial или собирает по порядку, промахнётся.
   - Постквантовый ClientHello (~1,8 КБ) и так занимает два Initial-пакета. Это уже даёт разрез бесплатно, если имя попадает во второй.
   - **Реализация:** патч упаковщика CRYPTO в quic-go внутри sing-quic.
3. **Изменение длины.** У Hysteria2 и QUIC вообще PADDING-фреймы допустимы, поэтому длину датаграмм можно делать случайной без изменений на сервере. У AWG это S1–S4.
4. **Ротация портов по расписанию**, как слоты SPA v2. Hysteria2 уже умеет port hopping. Согласованная версия: порт выводится из общего ключа и времени, как в SPA v2. Сервер (udpmux) слушает порты текущего и соседних слотов, клиент вычисляет их сам. Это сбивает пороги «по потоку», в том числе предел около 25 пакетов, если он действует на UDP.
5. **Сигнатурные пакеты (мимикрия).** Для AWG I1–I5 уже есть в нашем порте AWG 2.0 [проверено: `transport/wireguard/device_awg.go`, импорт `.conf` в клиенте]. Для QUIC протоколов аналог — пункт 1. Ограничение: DPI, который смотрит дальше первых пакетов, мимикрию видит. Это не замена обфускации.

### TCP со стороны сервера

- **Маленькое окно TCP в SYN-ACK** (идея wsize). Сервер (фронт niko-server, сокет на 443) объявляет окно меньше ClientHello. Любой клиент тогда вынужденно разрезает ClientHello по сегментам, без изменений на клиенте.
  - Против ТСПУ, который собирает сегменты, это не поможет. Против более простых DPI — поможет.
  - Цена: лишний RTT на рукопожатие.
  - Включать флагом и проверять на тестовых точках.
- **Предел около 16 КБ на поток** лечится не техниками десинхронизации, а формой трафика:
  - много коротких соединений (XHTTP в режиме packet-up с ротацией соединений; в ядре клиента XHTTP есть);
  - UDP-протоколы, если UDP не режется;
  - узел в белой подсети: входная нода внутри страны, решение B-3 raycontrol (цепочки).

### Риск SPA v2 на UDP

Это главный вывод для raycontrol. Сейчас на мобильных сетях РФ сценарий «UDP закрыт, TCP 443 открыт» встречается часто [сообщают]. В нём SPA v2 не дойдёт, и REALITY станет недоступен целиком: порты закрыты до SPA.

Предложение (решать raycontrol):
- **SPA поверх TCP как второй носитель.** Тот же пакет SPA v2 отправляется первыми данными TCP-соединения на порт слота.
  - `rayspa` видит его через NFLOG на первом сегменте с данными. Рукопожатие на этот порт проходит через nftables `synproxy`, сокета нет. После пакета соединение сбрасывается.
  - Минус: порт слота отвечает на SYN, то есть его видно сканеру. Но он ротируется по слотам и ничего не отдаёт.
- Клиент: если ответа на подключение после UDP-SPA нет, повторить SPA по TCP. Повтор при неудачном подключении в клиенте уже есть (`spa-v2.md` §7), нужен только второй носитель.
