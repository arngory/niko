**Что из этого следует.** Десинхронизация (термин zapret) ломает классификатор, который решает по первым пакетам. Он
должен увидеть не то, что получит сервер. Против SNI в TCP и QUIC это работает, если сайт не заблокирован ещё и по
IP. Не работает против блокировки по IP, предела «16–20 КБ», режима белых списков и удаления домена из DNS. От DNS
у Niko уже есть удалённый DNS, остальное решается узлом, а не трюками. Набор работающих трюков меняется по
операторам и месяцам [источник: zapret2 — «старые перестают работать»](https://github.com/bol-van/zapret2). Поэтому
без пробы на сети пользователя (раздел 5.3) ни одна стратегия по умолчанию не годится.

## 2. Два применения в Niko

**(а) Прямой трафик, без сервера.** Правила маршрута отправляют что-то напрямую, но DPI режет это по SNI. Примеры:
- YouTube и Discord у пользователя без узла;
- то же у пользователя, который бережёт трафик узла;
- российские сайты, у которых внереестровый блок по SNI на части сетей.

Здесь Niko работает как ByeByeDPI. Тот же VPN-режим Android, а ByeDPI внутри — это ядро Niko. Узел не нужен.

**(б) Свои соединения к узлам.** Рукопожатия REALITY, VLESS-TLS, Trojan, naive и QUIC у Hysteria2 и TUIC. У
REALITY SNI и так разрешённый. Мешают ASN, объём и отпечаток, а против них десинхронизация почти бессильна (раздел
1). Остаётся узкий случай: классификатор по первому пакету рукопожатия. Для QUIC это уже покрыто `udpdesync`. Для
TCP — фрагментацией в профиле. Новое здесь только после замеров на L-2.

## 4. Техники

Ключевой факт. На Android трафик других приложений заканчивается в gVisor (sing-tun), а наружу **ядро Niko само
открывает TCP-сокет** (защищённый `VpnService.protect`). Мы на месте ByeDPI за hev-socks5-tunnel в ByeByeDPI. Поэтому
всё, что ByeDPI делает на своём сокете, переносится один в один. Всё, что nfqws делает через NFQUEUE и raw-сокеты, без
root не переносится: zapret прямо пишет, что без root на Android остаётся только `tpws --socks`
([источник: zapret, Android](https://github.com/bol-van/zapret/blob/master/docs/readme.md#android)).

Второй факт. **Байты чужого ClientHello менять нельзя.** Они входят в хеш рукопожатия: браузер посчитал хеш по
своим байтам, сервер — по полученным, и проверка `Finished` не сойдётся. Поэтому для прямого трафика годится только
то, что меняет нарезку:
- TCP-сегменты;
- TLS-записи: их заголовки в хеш не входят;
- порядок отправки;
- добавочные пакеты.

Регистр SNI, padding и сжатие ClientHello доступны только для собственных рукопожатий к узлам, где ClientHello строим
мы. Для простого HTTP хеша нет, и трюки с `Host` там возможны.

## 5. Устройство

### 5.1 Ядро: `common/tcpdesync` (Niko)

Обёртка соединения на первую запись, как `tf.Conn`, но со стратегией:

```json
"tcp_desync": {
  "split": [{"at": "1", "mode": "split"}, {"at": "sni+1", "mode": "disoob"}],
  "tlsrec": ["sni+2"],
  "oob_byte": "a",
  "fake": {"ttl": 5, "sni": "allowed.example", "md5sig": false},
  "auto": {"on": ["torst", "ssl_err"], "timeout": "3s", "next": ["disorder1", "fake"]}
}
```

- **Маркеры** — как в zapret и ByeDPI:
  - число, отрицательное — от конца;
  - `host`/`sni`, `endhost`, `sld`, `midsld`, `sniext`;
  - смещение `+N`/`-N`.

  Маркер считается по собранной записи ClientHello: постквантовый ClientHello больше MSS, и позиции нормализуются,
  как в zapret. Если маркера в протоколе нет, разреза по нему нет.
- **Режимы**: `split`, `disorder` (TTL=1), `oob`, `disoob`, `fake` (1.68). `tlsrec` применяется до нарезки.
- **Буфер первой записи.** Обёртка ждёт целую запись ClientHello: до 16 КБ + 5 байт и не дольше 200 мс. Иначе
  пропускает данные как есть и пишет об этом в журнал один раз.
- **Без сна на 500 мс.** Отдельный сегмент гарантируется пустой очередью неотправленного (`TCP_INFO`), а не
  подтверждением. Подтверждение ждём только для `disorder` и `fake`, где без перепосылки никак. Старые
  `tls_fragment`/`tls_record_fragment` остаются как есть: апстрим. Приложение их больше не ставит (5.2).
- **Где применяется.**
  - Правило маршрута: `tcp_desync` в `RawRouteOptionsActionOptions`, рядом с `tls_fragment`. Действует, только если
    под соединением `*net.TCPConn`, то есть прямой исходящий. Для проксируемого — предупреждение и ничего: резать
    поток внутри туннеля бессмысленно.
  - TLS исходящих: `desync` с той же структурой, рядом с `fragment`.
- **Стратегия «auto».** Правило может сослаться на стратегию по имени (`"tcp_desync": {"use": "auto"}`). Её
  содержимое libcore меняет на ходу (`SetDesyncStrategy`), без перезапуска ядра: приложение подставляет стратегию
  текущей сети (5.3).
- **auto в соединении.** Соединение держит свой первый полёт, пока не придёт первый байт ответа. Если до этого
  пришёл RST, вышел таймаут или вместо ServerHello пришло не то (`ssl_err` в терминах ByeDPI), ядро:
  1. набирает тот же IP заново;
  2. отправляет первый полёт со следующей стратегией из `next`;
  3. запоминает номер стратегии в памяти по ключу (сеть, хост) на 28 ч, как ByeDPI.

  Клиент видит только задержку. Сделать так можно лишь до первого байта ответа клиенту.
- **UDP.** Правило маршрута `udp_desync` с той же структурой, что `option.UDPDesyncOptions`. Обёртка ставится в
  `NewPacketConnection` для прямого исходящего: прелюдия с TTL и перестановка Initial, тот же код `udpdesync`.
- **Возможности платформы.** При запуске ядро пробует `IP_TTL` на TCP, `MSG_OOB`, `vmsplice`, `TCP_MD5SIG` и
  `TCP_INFO` и сообщает приложению. Стратегии с недоступным приёмом приложение не предлагает.

### 5.2 Приложение

- **«Обход DPI для прямых соединений»** вместо «Фрагментации TLS для прямых правил». Значения:
  - Выключено (по умолчанию);
  - Авто — стратегия, найденная пробой в этой сети;
  - Готовая — пресет;
  - Своя — строка в синтаксисе ByeDPI (подмножество `-s -d -o -q -r -f -t -n -S -A`, ровно то, что умеет ядро).

  Пользователи переносят стратегии строками ByeDPI с ntc.party и byebyedpi.org. Принимать их — дешевле, чем учить
  новый синтаксис. Строки nfqws (`--dpi-desync=…`) не принимаем: почти всё в них — raw.
- **Миграция.** Старое значение 1 (записи) → пресет «tlsrec по SNI», 2 (TCP) → «разрез по SNI».
- **Куда ставится.** Не на все правила «напрямую», а на отмеченные: у правила флажок «Обход DPI».
  - У правила «РФ напрямую» из пресета флажок **выключен**: российские сайты по SNI не режут, а цена — лишняя
    задержка на каждом соединении.
  - Новый пресет «Заблокированное — напрямую с обходом DPI» для пользователя без узла: наборы runetfreedom по
    сервисам (YouTube, Discord; имена файлов сверить). Флажок включён, QUIC этих сервисов — в «QUIC → TCP» или
    `udp_desync`.
- **Профиль узла.** «Фрагментация TLS» становится «Обходом DPI в рукопожатии» с теми же пресетами, без фейков (5.4).

| Что | По умолчанию |
|---|---|
| Прямые правила вообще | выкл. |
| Правило «РФ напрямую» | выкл. |
| Пресет «Заблокированное напрямую» | вкл., «Авто»; до пробы — `tlsrec sni+1` (даром и безопасно) |
| Фейки по TTL | только с TTL, найденным пробой в этой сети |
| Рукопожатия к узлам | как сейчас (выкл.) |

### 5.3 Проба (как blockcheck) и память по сети

- **Где.** Пакет `libcore/dpiprobe`, вызов из экрана прогона проверки (рядом с `RayTestRun`) и кнопкой в
  настройке. В фоне сама не запускается: обращения к заблокированному идут с IP пользователя.
- **Цели.** Список виден и правится. По умолчанию — домены включённого пресета. Адреса — через удалённый DNS
  Niko: подмену DNS проба не должна принимать за DPI.
- **Шаги для каждой цели.**
  1. TCP-подключение. Нет подключения — «блок по IP», дальше не идём.
  2. TLS без обхода. Прошло — «не блокируется».
  3. Чтение 64 КБ. Замерло на 16–20 КБ — «предел объёма»: трюки не помогут, нужен узел.
  4. Стратегии по возрастанию цены, каждая 3 раза: `tlsrec` → `split` → `oob`/`disoob` → `disorder` → (1.68)
     `fake` с перебором TTL снизу вверх.

     Успех — ServerHello с сертификатом на это имя и прочитанные 64 КБ. Для QUIC — ответ на Initial без обхода,
     с прелюдией и с перестановкой.
- **Итог.** Самая дешёвая стратегия, которая прошла для всех целей. Для фейка — найденный TTL минус один, нижний
  край рабочего диапазона. Хранится по ключу `RayChannel.network()`, только на устройстве. При смене сети
  приложение подставляет её в «auto» (5.1). Срок, как у канала: 7 дней в Wi-Fi, сутки в мобильной сети.
- **Бюджет.** До 60 с и до 2 МБ на мобильной сети. В отчёте прогона — стратегия, характер блока по каждой цели и
  возможности платформы.

### 5.4 Соединения к узлам

- **Оставляем как есть:**
  - фрагментацию в профиле;
  - `udpdesync` для QUIC.
- **Добавляем** только пресеты `tcpdesync`: `split`, `tlsrec`, `oob`. Фейк к узлу по умолчанию не ставим: с неверным
  TTL фейк попадёт в поток REALITY, и рукопожатие сломается.
- **Своё рукопожатие можно менять глубже**, ClientHello строим мы: padding, чтобы SNI ушёл во второй сегмент. Но
  эталон Chrome ([fingerprint.md](fingerprint.md)) мы держим ради неотличимости, и отход от него — отпечаток. Решать
  после замеров.
- **Против «16–20 КБ» и заморозки по отпечатку** работает другое (решения в [anti-dpi.md](../research/anti-dpi.md)):
  - ротация соединений (XHTTP);
  - входной узел в РФ;
  - mux: меньше параллельных рукопожатий к одному SNI.
- **Свой сервер сильнее чужого.** niko-server может сообщать клиенту число хопов по TTL в SYN клиента (64 минус
  полученное). Тогда TTL фейка к своему узлу не надо подбирать. Это работа raycontrol, позже.

### 5.5 Компьютер

`nikod` работает службой (SYSTEM на Windows, root на Linux), и raw доступен:
- **`tlsspoof`** уже даёт фейк с `wrong-sequence`/`wrong-checksum`/`wrong-md5`/`wrong-timestamp` без калибровки
  TTL. На Windows — через WinDivert.
- **Та же стратегия JSON.** `fake.method` выбирает TTL (Linux, Android) или raw (компьютер).
- **Перепосылка на Windows** начинается с первой потери. Для `disorder` там нужен `split` перед ним, как советует
  ByeDPI. Пресеты — по платформам.
- **Позже — WinDivert для seqovl и фейков на уровне пакетов**, как в zapret2. Только при спросе и после Android: на
  Windows у пользователей уже есть GoodbyeDPI и zapret.

|---|---|---|---|

Проба возможностей платформы | «Обход DPI для прямых соединений»: выкл., пресеты, строка ByeDPI (без `-f`, `-A`); флажок у правила; миграция старой настройки | юнит и петля (ниже); снимки `golden` конфига; ручная проверка на SIM двух операторов против ByeByeDPI с той же строкой |

**Почему 1.67 такой.** Всё в нём без root, без калибровки и не может испортить поток чужого сервера: сервер
получает ровно те байты, что отправил клиент. Из-за перестановки или OOB сломается разве что мидлбокс, и тогда
пользователь выключит пресет. Фейки и автоподбор опасны, если промахнуться с TTL, поэтому идут вместе с пробой.

### Тесты

- **Юнит в форке.**
  - Маркеры на настоящих ClientHello: эталон Chrome (`chromehello/hello.hex`), постквантовый на 1,8 КБ, без SNI, с
    ECH.
  - План нарезки — чистая функция. Склейка кусков равна исходному потоку, если не считать OOB-байта и заголовков
    записей.
  - Выход `tlsrec` разбирается Go `crypto/tls` сервером.
- **Петля (Linux).** На каждый режим: сервер читает ровно исходные байты, для OOB — без `SO_OOBINLINE`. Буфер первой
  записи при ClientHello из двух `Write`. Нет сна, если ACK быстрый.
- **Симулятор DPI в CI (1.68).** Сети в `ip netns` на раннере Linux (там есть sudo):

  ```
  клиент — r1 (DPI) — r2 — r3 — сервер
  ```

  На r1 стоит программа на Go с NFQUEUE (`florianl/go-nfqueue`). У каждой модели DPI свой приём, который её
  обходит:

  | Модель | Обходит |
  |---|---|
  | SNI в одном пакете, без сборки | `split` |
  | сборка по порядку до 2 КБ | `disorder`, `fake` |
  | разбор одной TLS-записи | `tlsrec` |
  | URG-байт идёт в поток DPI | `oob` |
  | решает по первому ClientHello | `fake` |
  | расшифровка первого Initial QUIC | прелюдия, перестановка |
  | счётчик 16 КБ к «зарубежному» адресу | ничто: проба должна сказать «предел объёма» |

  Фейк с TTL 2 умирает на r2. С TTL 5 доходит до сервера, и тест ждёт сломанного соединения: так проверяется, что
  проба это распознаёт. Идея моделей — у [цензоров Geneva](https://github.com/Kkevsterrr/geneva/tree/master/censors).
  Симулятор проверяет механику (байты на проводе, целость потока, бюджет TTL), а не действенность против ТСПУ.
- **Android.** Проба возможностей на эмуляторе в e2e (его ядро не телефонное) и на двух-трёх телефонах руками:
  `vmsplice`, `TCP_MD5SIG`, `MSG_OOB`.
- **Настоящие сети.** Тестовые точки L-2 (RU: проводной и мобильный) и `dpi-ch` для характера блока. Сравнение с
  ByeByeDPI на той же SIM и той же строке.

## 7. Вопросы владельцу

1. **По умолчанию выключено везде?** Включается пресетом «Заблокированное напрямую», флажком правила или пробой.
   *Рекомендация: да.* Стратегии по умолчанию для всех сетей не существует (раздел 1), а лишняя задержка на
   российских сайтах ударит по всем.
2. **Принимать строки ByeDPI (подмножество) в приложении при своём JSON в ядре?** *Рекомендация: да.* Пользователи
   переносят стратегии строками. Строки nfqws — нет.
3. **Фейки (1.68) — только с TTL, найденным пробой в этой сети?** Ручной TTL — в «Своей» строке, с предупреждением.
   *Рекомендация: да.* Промах по TTL ломает соединение, а не просто не помогает.
4. **Проба — только по кнопке, со списком целей на виду?** *Рекомендация: да.* Она обращается к заблокированному с IP
   пользователя мимо узла.
5. **Рукопожатия к узлам до замеров L-2 не трогаем?** Только пресеты разреза в профиле, без фейков и без отхода от
   эталона Chrome. *Рекомендация: да.* Против того, что режет узлы сейчас («16–20 КБ», заморозка по отпечатку),
   десинхронизация не помогает.
