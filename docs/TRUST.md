# Доверенные корни: что чему следует

Состояние на 1.48.0 (2026-11-14). Решения владельца отмечены датой.

## Настройка «Доверенные корневые сертификаты»

Три значения: список Chrome (по умолчанию), список Mozilla, системное хранилище вместе с корнями, установленными
на телефон. Списки Chrome и Mozilla — те, что несёт ядро этой версии приложения (`common/certificate/chrome.go`,
`mozilla.go` в форке ядра; в 1.47.0 — 92 и 161 корень), они меняются с обновлением приложения.

Настройке следуют:
- исходящие ядра с TLS из Go и uTLS (trojan, vless, vmess, hysteria2, tuic, anytls, shadowtls и др.) и удалённый DNS;
- HTTP-клиент приложения: подписки, наборы правил, обновления, проверка DNS-туннелей (DoT, DoH).

Импортированный `ca.pem` (Маршруты → Ресурсы) добавляется к любому из трёх значений и список не заменяет.
Собственный сертификат профиля и пины ключа действуют поверх настройки, как и раньше.

Полный конфиг sing-box, заданный профилем: если он сам называет список (`certificate.store`), остаётся его список;
если только добавляет сертификаты — получает список из настройки и импортированный `ca.pem` вместе со своими.

## naive

naive — это сетевой стек Chromium внутри библиотеки приложения, и корни он проверяет сам. Настройке приложения
он **не следует**.

Что известно:
- без сертификата в профиле Chromium проверяет по собственной копии списка Chrome и, по коду библиотеки, по
  корням из `/system/etc/security/cacerts` (системные корни Android; на Android 14+ система обновляет их в другом
  каталоге, так что набор может отставать);
- корням, которые установил пользователь телефона, naive не верит. Проверено на эмуляторе Android 14 с
  библиотекой из APK (Chromium 158): сервер под таким корнем отклоняется («cert authority invalid»), в том числе
  при настройке «системные»;
- сертификат в поле профиля **заменяет** оба списка для этого профиля (так устроен вызов библиотеки), и только с
  ним naive по QUIC принимает сервер под собственным корнем: без него QUIC требует корень из списка Chrome;
- пины ключа (`niko-pin`, поле «Пиннинг сертификата») проверяются вместе с цепочкой, а не вместо неё.

Не проверено на устройстве: что naive действительно принимает корень из системного каталога, которого нет в
списке Chrome (по TCP — да, по QUIC — нет, по разбору кода).

### Решено (2026-11-14)

1. **По умолчанию naive должен доверять только списку Chrome**, без системного каталога Android; доверие системным
   корням — опция, которую можно включить. Сейчас это не так: библиотека читает системный каталог всегда. Правка
   — в сборке библиотеки (серверная сторона) и в приложении, которое должно передать выбор. Не сделано.
2. **Импортированный `ca.pem` на naive не действует, и делать это не будем.** Свой корень для naive-сервера
   вписывается в поле сертификата профиля. Причина: вызов библиотеки заменяет список, а не дополняет его;
   добавка потребовала бы правки библиотеки, и по QUIC такой корень всё равно не прошёл бы. Это известный пробел, а
   не ошибка: поведение `ca.pem` для naive и для остальных исходящих разное.

## Известные пробелы

- `ca.pem` не действует на naive (решение 2 выше).
- naive доверяет системным корням Android независимо от настройки (до выполнения решения 1).
- Значение «список Mozilla» на naive не распространяется: у Chromium только свой список.
- Какие корни naive берёт из системного каталога, на устройстве не проверялось.
- Соединения приложений пользователя через туннель проверяют сами приложения; настройка на них не влияет.
