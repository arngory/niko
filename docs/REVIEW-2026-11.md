# Ревью Niko: безопасность, устойчивость к блокировкам, производительность, качество (2026-11-04)

Срез на клиенте v1.25.0 (`675974b`), ядро `c01924a`, raycontrol v0.8.0.

**Как делали.**
- Четыре независимых ревью: безопасность протоколов и секретов, поверхность Android-приложения и утечки,
  производительность и батарея, внешний ресёрч блокировок (2024–2026).
- Качество смотрели отдельно.
- Ключевые находки перепроверены по коду, ссылки на файлы указаны.
- Пометка **[1 ист.]** — утверждение из одного источника или по отчётам сообщества, без подтверждения.

## 0. Коротко

- **Протоколы raycontrol в клиенте сделаны добротно.**
  - SPA v2 по спецификации.
  - Обе подписи подписки проверяются до разбора.
  - Пины SPKI, только X25519MLKEM768.
  - Ключи устройства в Android Keystore.
  - mTLS администратора.
  - Interop против настоящих серверных компонентов.
- **Слабые места — вокруг протоколов.**
  1. Всё, что приходит снаружи (ссылки, подписки, QR, JSON-конфиги), попадает в ядро почти без фильтра. В худшем
     случае присланный JSON заставляет ядро запустить бинарник.
  2. Журналы и экспорт отладочной информации содержат секреты.
  3. Отпечаток TLS устарел: uTLS Chrome 133, по сообщениям его уже прицельно режет ТСПУ.
  4. Фоновая логика держит радио и ядро активнее, чем нужно, и местами перезапускает ядро зря.
- **Что делать до первых тестов на VPS** (§6): редактирование журналов, строгий разбор строк подписки raycontrol,
  запрет исполняемых опций из импорта, обновление отпечатка TLS. Без первого логи с проверки сами станут утечкой.
  Без последнего проверка может провалиться из-за отпечатка, а не из-за сети.

## 1. Безопасность

### 1.1. Высокое

**S1. Присланный JSON заставляет ядро запустить бинарник** (подтверждено).
- Исходящий `tor` зарегистрирован (`libcore/box_include.go:79`), его `executable_path` идёт прямо в `exec`
  (`sing-box/protocol/tor/outbound.go:79`).
- `adapter.SecurityPolicy` в libcore не задан.
- Пути в ядро:
  - подписка с JSON sing-box — `ConfigBean type=1`, фильтруются только `dns/block/direct/selector/urltest`;
  - `customOutboundJson` (его не чистит `RawUpdater`);
  - Kryo-ссылки `sn://`.
- Срабатывает при подключении и даже при тесте задержки: `TestInstance` поднимает все исходящие.
- Полной цепочки до RCE нет (ведущие флаги tor ломают `sh`/`toybox`), но это примитив запуска из удалённого ввода.
- **Исправить:**
  - `SecurityPolicy` в `NewSingBoxInstance` с запретом tor (и любых `*_path` и запуска процессов);
  - список разрешённых типов исходящих для всего, что пришло из подписки или ссылки;
  - очистка `customOutboundJson` у строк подписок.

### 1.2. Среднее

**S2. Строки подписки raycontrol разбираются общим импортёром** (подтверждено).
- `RaySubscription.kt:150` → `parseProxies` принимает любые схемы, включая `sn://` с полным конфигом и
  `customConfigJson`.
- Новые строки сохраняют присланные `customConfigJson`/`customOutboundJson`.
- REALITY без `pqv` не отвергается, хотя `subscription-v1.md` §4 этого требует.
- `Util.zlibDecompress` без предела: 3 МБ `sn://` раздуваются в гигабайты, и процесс падает по OOM.
- **Кто может:**
  - скомпрометированная нода с обоими ключами подписи;
  - любая веб-страница: `rcinv1:` открывается из браузера, и после одного «Да» устройство регистрируется на ноде
    атакующего. Дальше её подписка может, например, поставить `route.final=direct` и открыть `mixed` на `0.0.0.0`.
- **Исправить:**
  - свой разборщик для строк raycontrol: по `kind` сервиса только `vless://`, `hysteria2://`, `naive+https://`,
    `naive+quic://`, `https://` для DoH;
  - без `sn://` и без присланного JSON;
  - `pqv` и `encryption` для REALITY обязательны;
  - предел распаковки в `zlibDecompress`.

**S3. Секреты в журнале и в экспорте отладочной информации** (подтверждено).
- `ProxyInstance.kt:28` пишет полный конфиг в `neko.log` при любом уровне журнала выше 0. Это пароли, UUID, ключи
  WireGuard, сид Yggdrasil устройства, секрет Clash API, пароль локального прокси.
- `SendLog` прикладывает `neko.log` и `logcat` целиком.
- Строки `Logs.i("raycontrol ${node.host}…")` раскрывают адрес ноды, хотя `RayDiagnostics` его вырезает.
- **Исправить:** убрать вывод конфига (или только в debug-сборке) и редактировать на уровне приёмника
  (`NekoLogPrintln`): известные хосты нод, IP, `password|uuid|private_key|secret|token`.

**S4. `ca.pem` и гео-базы из внешнего хранилища** (подтверждено).
- `libcore/certs.go`: `ca.pem` из `getExternalFilesDir` *заменяет* корневые сертификаты.
- На Android 6–10 туда может положить файл любое приложение с доступом к хранилищу или USB-хост. После этого все
  соединения без пина открыты для MITM: TLS-прокси, удалённый DoH, загрузка подписок и гео-баз.
- `geoip.db` и `geosite.db` оттуда же можно подменить и увести трафик в обход.
- **Исправить:** доверие и правила маршрутизации — только из `filesDir`; `ca.pem` — явный импорт и добавление к
  системным, а не замена.

**S5. Обход пути при импорте файла гео-базы.** `AssetsActivity.kt:101-116` строит путь из имени, которое отдаёт
сторонний `DocumentsProvider`; проверяется только `.db`. Имя `../../…/databases/configuration.db` перезапишет
настройки. **Исправить:** `File(name).name` и проверка канонического пути.

**S6. Импорт из QR, буфера и файла идёт без подтверждения.**
- Подтверждение с предупреждением о полном конфиге есть только у deep-link.
- `customConfigJson` сливается поверх всего конфига. Например,
  `{"inbounds+":[{"type":"mixed","listen":"0.0.0.0"…}],"experimental":{"clash_api":{"external_controller":"0.0.0.0:9090","secret":""}}}`
  открывает прокси и Clash API на Wi-Fi.
- **Исправить:** один диалог на все пути импорта со списком переопределяемых ключей верхнего уровня.

**S7. «Разрешить входящие» в Yggdrasil открывает mesh собственные слушатели приложения.**
- Входящие соединения mesh направляются на `127.0.0.1:port` напрямую.
- Под это попадают `mixed` без пароля в режиме «только прокси» и SOCKS-порты плагинов naive, mieru и trojan-go без
  пароля.
- Любой узел mesh может пользоваться прокси пользователя. **Исправить:** запретить свои порты.

**S8. Плагины доверяются по префиксу authority** (`Plugins.kt:46-75`). Любое приложение с провайдером
`moe.matsuri.exe.*` подсунет свой бинарник для naive, mieru, trojan-go и hysteria-faketcp. Он работает под UID
Niko, читает профили и пользуется сокетом protect. **Исправить:** пин подписи плагина или подтверждение
пользователем; встроенный `.so` — в приоритете.

**S9. SPA v1: время отправки в открытом виде** (`knock/spa.go:46,56`). Байты 16–23 — время Unix, байты 16–19 нулевые.
Простое правило DPI опознаёт каждый стук. Для SPA v2 (raycontrol) не относится. **Исправить:** маскировать
время или перевести v1 на AEAD, как v2.

### 1.3. Низкое

- Повторный импорт ноды сбрасывает `subSeq` в 0 (`RayNodes.kt:259`): одна старая подписка может пройти. Нужен
  также TLS-ключ ноды.
- Приглашение администратора показывается без `FLAG_SECURE` и копируется без пометки «чувствительное»
  (`RayAdminActivity.kt:357`).
- SOCKS-порты плагинов и inbound-ы проброса открыты всем локальным приложениям, в том числе исключённым из VPN.
- Экспорт конфига содержит глобальный ключ Yggdrasil, секрет Clash и пароль `mixed` (`ConfigBuilder.kt:334, 216`).
- Режим «только прокси»: подписка при сбое SOCKS молча качается напрямую с реального IP (`libcore/http.go:117`).
- Повторы SPA v2 при сбое не объединяются между параллельными дозвонами (`spa2.go:283`). Это всплеск пакетов на
  смене слота, есть риск упереться в лимит nftables ноды.
- HTTP-клиенты raysub, rayapi и rayprobe следуют редиректам. Стоит `CheckRedirect: http.ErrUseLastResponse`.
- `quic://` пиры Yggdrasil в режиме «только прокси» резолвятся системным резолвером (в VPN-режиме мы это
  обошли в v1.21.0).

### 1.4. Проверено и в порядке

- **SPA v2** — по спецификации: HKDF, AAD, случайный nonce XChaCha, длина в диапазоне, порт слота по HMAC,
  продления.
- **Подписка raycontrol:**
  - обе подписи (Ed25519 и ML-DSA-65) обязательны до разбора, проверяются `node_id`, `seq` и `expires`;
  - пин SPKI работает и при возобновлении сессии;
  - предел тела 4 МиБ.
- **rayapi:** клиентский сертификат на каждом соединении, MAC привязан к пину, повторной отправки записанного
  запроса нет, ротация по спецификации.
- **Ключи:** ключи устройства и mTLS обёрнуты неэкспортируемым ключом Keystore; в ядро идёт ссылка, не ключ;
  бэкап и экспорт ключей не несут.
- **Экспортируемые компоненты Android:** сервисы и FileProvider не экспортированы; deep-link-и `rcinv1`/`rcdev1`
  всегда спрашивают.
- **VPN:** нет `allowBypass`, приложение внутри VPN, IPv6 без адреса блокируется, порт 53 перехватывается.
- **Локальные слушатели:** Clash API на `127.0.0.1` со случайным секретом; `mixed` с паролем в VPN-режиме.

## 2. Устойчивость к блокировкам (ресёрч)

### 2.1. Что происходит (Россия, 2025–2026)

- **Заморозка после ~16–20 КБ.** TCP к зарубежным хостингам (Hetzner, DO, OVH, Cloudflare) встаёт без RST, в
  основном на мобильных сетях, с лета 2025, сообщения есть и в октябре 2026 (Cloudflare blog, net4people #490).
  Касается и REALITY.
- **Белые списки на мобильном интернете** (с сентября 2025).
  - Работают по IP/CIDR; подмена SNI перестала помогать.
  - В режиме белого списка UDP 443 и UDP 53 режутся даже к разрешённым IP **[1 ист.]**.
- **QUIC** (FOCI 2026, измерения март–апрель 2026).
  - ТСПУ расшифровывает Initial QUICv1 и блокирует по SNI тем же списком, что TLS.
  - После блокировки 420 с на четвёрке адресов.
  - QUICv2 не трогают.
  - SNI нашей ноды в этих списках нет, поэтому для Hysteria2 и naive-quic реальные ограничения — заморозка и
    белые списки.
- **Отпечатки и залпы рукопожатий.**
  - Ноябрь 2025: у части домашних провайдеров перестал работать REALITY+Vision на 443; помогали mux, отказ от
    Vision или другой порт (net4people #546).
  - 2026: больше 3 одновременных ClientHello к одному хосту дают заморозку на 120–600 с **[1 ист., пороги]**.
  - Октябрь 2026: **отпечаток uTLS Chrome 133 тормозят или блокируют** (Xray #7131).
- **IP банят пачками каждые 6–12 часов, целыми подсетями хостингов.** Источник адресов, по словам VPN-провайдеров, —
  данные российских приложений **[1 ист.]**.
- **DoH и DoT к Google и Cloudflare** блокируются у Билайна, Ростелекома и Дом.ру с середины августа 2026.
- **Проверка VPN в приложениях.**
  - С 15 апреля 2026 крупным платформам предписано выявлять VPN; один из способов — сравнить российский и
    зарубежный запрос изнутри приложения, что ловит раздельное туннелирование по доменам.
  - 30 из 30 топ-приложений проверяют VPN: `TRANSPORT_VPN`, `tun0`, свойства прокси, `/proc/net/tcp` (RKS Global).
- **Brutal опознаётся простым порогом:** он не сбрасывает темп при сигналах перегрузки (FOCI 2025).
- **Чего не нашли:** прицельных блокировок Yggdrasil, NaiveProxy и dnstt в России; исследований атак на SPA;
  признаков отпечатков QUIC Initial на ТСПУ.

## 3. Производительность, батарея, трафик

**P1. Радио не засыпает: QUIC Hysteria2 не закрывается в простое.**
- sing-quic шлёт keepalive раз в 10 с, `keep_alive_period` мы не задаём.
- Пока сокет жив, knock продлевает SPA каждые 5–8 мин.
- Плюс проверка watchdog раз в 10 мин.
- **Исправить:** `keep_alive_period` около 25 с для Hysteria2 ноды; в Doze пропускать проверки watchdog.
- **Мерить:** `batterystats` за 2 ч простоя на мобильной сети: Hysteria2, VLESS, VPN выключен.

**P2. Подписка повторяется каждые 15 мин без отсрочки** (подтверждено, `RaySubscription.kt:87`).
- Ошибка «не ответила» означает и DNS, и дозвон, и сбитые часы.
- Каждый неудачный запрос — около 45 с под wakelock; запуск идёт и при выключенном VPN.
- **Исправить:** экспоненциальная отсрочка от 15 мин до 6 ч, сброс при успехе или смене сети.

**P3. Brutal: лишние перезапуски ядра** (подтверждено, `RayBrutal.kt:104`).
- Когда истекают сутки, темп сравнивается до нового замера: перезапуск на BBR, затем замер и ещё один перезапуск.
  То же в новой сети.
- Снижение по `ack_rate` при стабильных 10–20 % потерь может каскадом давать перезапуск каждые ~10 мин.
- Каждый перезапуск рвёт все соединения; без «Блокировать без VPN» в эти секунды трафик идёт мимо.
- **Исправить:** держать старый темп до нового замера; гистерезис ±20 %; после второго снижения — BBR до конца
  суток.

**P4. Трафик замеров Brutal.**
- 24 МиБ в сутки на Wi-Fi-сеть, 6 МиБ на мобильную. Раздача с телефона считается Wi-Fi.
- На 4xx и `Retry-After` повтор через час.
- Шаги `up` и эхо идут и после `429` на `down`.
- Нативный вызов не отменяется до 2 мин.
- **Исправить:** размер по `NET_CAPABILITY_NOT_METERED`; не мерить в роуминге; стоп после первого 4xx; учитывать
  `Retry-After`.

**P5. В группе-селекторе перезапуски watchdog ничего не делают** (подтверждено, `BaseService.kt:186`).
- Перезагрузка только переключает исходящий, поэтому новые учётные данные, темп Brutal и пиры Yggdrasil не
  применяются.
- Сборка временного конфига затирает `noteApplied` и `noteYggVia`, и watchdog считает, что всё применено.
- **Исправить:** у перезапусков watchdog — флаг «принудительно».

**P6. Холодный старт `:bg` собирает конфиг без сети.** Колбэк сети приходит позже, поэтому темп Brutal и пиры
Yggdrasil в первый конфиг не попадают: через ~20 с лишний перезапуск. **Исправить:** подождать сеть 1–2 с.

**P7. Мигающая сеть сбрасывает отсрочку восстановления.** Восстановление (подписка и N тестовых ядер) может идти
каждые ~5 мин; возможны качели A↔B. **Исправить:** сброс не чаще раза в 30 мин на сеть.

**P8. Процессор.**
- HMAC-SHA256 на каждую UDP-датаграмму в `knock/udpports.go:99` — кешировать на слот.
- Двойное копирование входящих пакетов Yggdrasil.
- `ConfigBuilder` в главном потоке `:bg` много раз разбирает JSON нод и расшифровывает ключ Keystore на каждый хоп.

**P9. Хранилище замеров растёт.**
- Ограничение по числу сетей есть только в `record()`; `_brutal`, `_hints`, `_report`, `_direct` и `_ygg_via`
  добавляют сети без обрезки.
- Каждая запись переписывает весь блок.

**Проверено и в порядке:**
- **watchdog и Doze:** один цикл; дочерние задачи уходят вместе с ним; будильников нет.
- **Горутины:** эхо, сессии и продления SPA завершаются; `go test -race` чистый.
- **Временное ядро проверки пиров:** закрывается за 6 с.
- **Межпроцессные записи:** под `RayNodesLock`.

## 4. Качество

- **Тесты:** 75 unit-тестов приложения в 21 файле; Go — knock 24, probe 9, rayprobe 9, raysub, rayapi; в ядре 9
  наборов `TestNeko*`.

## 5. Что собрать на проверке VPS

Привязано к гипотезам выше. Дополняет [`server/VPS-CHECK.md`](server/VPS-CHECK.md).

| Что | Как | Проверяет |
|---|---|---|
| Утечки | Захват на роутере или точке доступа при включённом VPN: только IP ноды и прямой DoH. Private DNS выключен, авто, строгий. IPv6-сеть. Смена Wi-Fi/LTE. Убить `:bg` | 1.4, R8 |
| Отпечаток TLS | Захват ClientHello к ноде, JA4, сравнить с Chrome stable на том же телефоне | R1 |
| Заморозка 16 КБ | Скачивание > 64 КБ одним соединением через REALITY на мобильной сети и на Wi-Fi; 4 параллельных рукопожатия | R2, R5 |
| Режим белого списка | «Проверить канал» на мобильной сети: UDP и MTU напрямую, носитель SPA | R2, R4 |
| Батарея | `dumpsys batterystats --reset`, 2 ч простоя с выключенным экраном: Hysteria2, VLESS, VPN выключен | P1 |
| Трафик | `dumpsys netstats detail` за сутки с Brutal | P4 |
| Перезапуски | `logcat \| grep -E "not this network's\|ack rate\|Brutal on this network\|switching from\|fetching the subscription"` | P3, P5, P7 |
| Журналы | Перед проверкой — исправить S3; затем уровень warn, экспорт, `grep -E "password\|uuid\|private_key\|secret"` | S3 |

## 6. Предлагаемый порядок

**До проверки VPS** — дёшево, и защищает саму проверку:
1. **S3** — редактирование журналов и экспорта. Иначе логи, которые мы попросим прислать, сами станут утечкой.
2. **R1** — актуальный отпечаток uTLS Chrome и JA4-сверка в CI. Иначе REALITY может не пройти из-за Chrome 133, и мы
   примем это за свойство сети.
3. **S2 и S1** — строгий разбор строк подписки raycontrol, предел распаковки, запрет tor и `*_path` из импорта
   (`SecurityPolicy`).

**После первых данных с VPS** — по измерениям:
- P1–P5: батарея, перезапуски, трафик замеров, селектор;
- R2 — вход через российский узел и детектор белого списка, вместе с сервером;
- R3 — без локальных портов, обход российских приложений целиком.

**Дальше:** S4–S9, качество (§4), R7 (форма SPA вместе с сервером).

**Серверной сессии:** R6 (размер сертификата сайта при ML-DSA-65), R2 (цепочка нод), R7 (SPA: повтор пакета,
привязка к IP и к рукопожатию, форма TCP-носителя).
